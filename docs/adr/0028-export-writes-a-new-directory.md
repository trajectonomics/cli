# Export writes a new directory, and JSONL stays the only importable format

`traj export --format jsonl|csv|md --out DIR` writes files, never stdout: `--out` is required and names a directory that must not exist. `--format` chooses the file format and `--json` chooses the Result's envelope; the two are separate axes and `--format` never changes the envelope. The command reads one dump and derives every file from it, so the formats cannot disagree about a row.

The directory is created race-safely: the parent recursively, then the target with a non-recursive `mkdir`, where `EEXIST` is `output_exists` at exit 5. So a typo cannot overwrite an older backup, and there is no `--force` in v1. A write that fails is `export_failed` at exit 1 with `path: "out"` and the absolute path in `details`, never the OS's own message; the directory this run created is removed, and a cleanup that itself fails says so in the hint. No file carries a timestamp, so two exports of the same database are byte-identical.

The JSONL file is the canonical export, unchanged from ADR-0017: the header with the format and schema versions, then one record per row in the fixed type order, every line ending in `\n`, tombstones included, money as decimal strings. It is the only format that restores.

CSV is for spreadsheets, one file per table. The first bytes are a UTF-8 BOM, so Excel detects UTF-8 and Thai text survives; lines end in CRLF per RFC 4180, the last included, and `.gitattributes` keeps a committed golden from being normalized. The header is the row's keys in the writer's declared order, the same keys the JSON rows use. `null` and an empty string are both an empty cell, an object is its compact JSON text, and a cell holding a comma, a quote or a line break is quoted with its quotes doubled. An empty table is its header only. CSV is not a restore format, and cells are written exactly as stored: a spreadsheet may coerce a numeric-looking cell and may run a cell that begins with `=`, `+`, `-` or `@`. The owner chose raw cells and documents that risk; the exact copy is the JSONL.

Markdown is one document, `traj.md`, with one section per table in record order: a heading with the table name and row count, then a pipe table with the same columns, `version`, `ordinal` and `amount` right-aligned. A backslash, a pipe, `<`, `>` and `&` are escaped in one pass so a memo cannot break the table or inject markup, and a newline becomes `<br>`. Inline `<br>` and those entities are the only HTML; there is no standalone HTML report. No timestamp.

## Considered options

Writing the export to stdout was rejected: one format is several files, and a redirected stdout cannot tell the caller which files it would have written. A default `--out` was rejected because it makes the destination implicit and makes an accidental second export overwrite the first. Overwriting with `--force` was rejected for v1: the safe mistake is cheap to fix, the destructive one is not. A zip, an XLSX, a manifest file or a server upload were rejected as out of scope; the issue defers the HTML viewer and asks for files a person can open. Escaping CSV cells to defeat spreadsheet formulas was rejected because the owner wants the stored value verbatim and the exact copy is the JSONL.

## Consequences

Two CLI-owned error codes join the registry: `output_exists` at exit 5 and `export_failed` at exit 1, each with a trigger in the contract test, so `traj schema` lists them and every failure keeps the envelope and exit class. Export is the first command that writes outside the data directory; a later `--force`, a per-table export or a restore command is a new decision, not a flag added quietly. The CSV golden and the Markdown golden are byte-exact over the Thai fixture, and the final spreadsheet check is the owner's own: open an exported CSV, see Thai text and the quoted cell. The automated tests assert the BOM, the CRLF, the header order and the quoting that make that check pass.
