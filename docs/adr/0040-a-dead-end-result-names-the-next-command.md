# A dead-end Result names the next command, in a field called `hint`

`traj` prints a result and stops. When that result is empty because the Ledger is empty, a person at a terminal is left with no next command: `traj init` prints three paths, `traj account list` prints `accounts:` and nothing under it, and a row of `0.00` does not say which command would change it. The order a first run needs — `init`, `account add`, `tx add`, `balance`, `report` — exists in the setup skill (ADR-0035), in the README's skill section and in the Factory's QA playbook, and nowhere in the binary.

A Result that has nothing to show carries one optional string field, `hint`, declared in its output schema beside the values it describes. `--json` prints it, and `traj schema` publishes it, because the output schema is the contract and it is generated from the definition that validates (ADR-0010). The human Format prints it as the last line, `hint: <sentence>`, which is where a failure prints its own `hint:` line (ADR-0013): the same word in the same place means the same thing, the command to run next. The sentence is prose, not a parsed command — a caller that wants to run it runs it, and one that wants the flags reads `traj help`.

The field appears only when the answer has no rows *and* the store explains why: no Account in the Ledger → the account sentence; an Account but no Transaction → the transaction sentence. That is narrower than "the answer is empty". `balance --as-of` before the Ledger's first Transaction is a true reading of the date the caller chose, so it stays hint-free, and `report networth` already states that state with `noTransactionsBefore` (ADR-0029). The sentence is chosen from the store, so the field never blames a caller's filter for an empty store, and the same read of the same store never prints one sentence today and another tomorrow.

`traj init` carries the account sentence only when it created the Ledger. A second `init` may find a chart of many accounts, and a sentence about a first account would then be false.

Both sentences live in one module with the predicate that picks between them, so `init` and the five reads cannot drift apart. A test runs the account sentence's quoted command against a fresh store, and compares the transaction sentence's flags with the command's own, because the sentence is a promise: a hint naming a command that fails, or a flag that no longer exists, is worse than no hint at all.

`UNKNOWN_ACCOUNT` is the other half of the same promise. It is raised by the write paths that resolve an account the caller named, and it carried no `hint` while every sibling failure already did; it now carries one sentence naming both the chart and the way into it. The Store's own `UNKNOWN_ACCOUNT`, raised for a stored posting that names no live account, keeps no hint: the account there is not the caller's input, and `account add` is not its fix.

## Considered options

A line on stderr was rejected: it is invisible to `--json`, and a successful command that writes outside its result cannot be captured or replayed. The table hint's `note` (ADR-0027) was rejected: a note is read only through a declared table hint, and only `inspect` and `projection run` declare one, so reaching a note from `init` would mean inventing a table; the note is also only the *name* of a result field, so it would have to be a published field anyway. A leaf `note` was rejected because that field is the release annotation (ADR-0034). A structured `next` object naming the command, its flags and its text was rejected as a second command grammar this repository would then own and validate; the envelope's own `hint` is already prose. A hint whose text changed with the chart was rejected for `UNKNOWN_ACCOUNT`: the same failure would read differently from one run to the next, which nothing else in the envelope does.

## Consequences

The field is additive and optional, so a consumer that ignores it sees the output it saw before, and a command's existing fields keep their names, order and types. `traj schema` grows one documented property per dead-end Result, and a golden that asserts a whole result object changes exactly once per command. The glossary gains **Hint** as the word for this sentence in both places it appears. A future read that can be empty on an empty store adds the same field and takes its sentence from the same module; a read that can be empty for another reason (a filter, a period) does not.
