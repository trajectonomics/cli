# The working directory runs nothing, and only `init` and `restore` create a ledger

`traj` is run by agents inside whatever directory a person is working in, and a repository can hold files that steer a tool. Four findings in the 8-persona QA of `@trajectonomics/cli@0.2.0` (cli#146) all come from that: a `bunfig.toml` with `preload = ["./pre.js"]` beside the shell made `traj --version` run `pre.js`; a `.env` there set `TRAJ_HOME` and redirected `traj init`; a read against a missing data directory answered `{"rows":[]}` at exit 0 and left an empty `traj.db` behind; and the ledger was `0644` inside a `0775` directory under umask 002. The first three are a tool that trusts its surroundings; the fourth is plaintext records of someone's money that anyone on the machine can read.

The compiled binary is the shipped surface, and every compile passes `--no-compile-autoload-bunfig` and `--no-compile-autoload-dotenv`, so neither file in the working directory is read. This is not a setting: `.github/workflows/binaries.yml`, `.github/workflows/installer-smoke.yml`, `bun run build` and the test that builds the shipped shape all carry the two flags, and `src/compiled.test.ts` fails a compile command that drops either. `TRAJ_HOME` still steers the ledger, because that is how a caller states where the data is; what goes away is a *file in the directory the command happens to run in* choosing for them.

`openStore` never creates a ledger. It fails with `ledger_missing` at exit 4, naming the `traj.db` path and pointing at `init`, for every command that has not said otherwise; two commands do. `traj init` creates an empty ledger, and `traj restore` creates one to write a backup into, because `traj data remove` deletes the database on purpose and the backup that guarded the removal is what puts it back (ADR-0038): the removal and the restore are the two deliberate commands that replace live data. No command creates a ledger as a side effect of reading one. A `TRAJ_HOME` that exists as a file is `not_a_directory` before that check, and a ledger the process cannot open keeps the typed failure of ADR-0037, so a wrong path is never reported as a missing one. An empty database created by a read is indistinguishable from a lost one — the QA persona read `{"rows":[]}` as "my data is gone", and a CI job read exit 0 as success — so the recovery instruction belongs in an error, not in silent success. `traj init`'s summary says it is the only command that creates an empty ledger and names `restore` as the other creator, which is what `traj schema` and `--help` print.

The data directory is created `0700` and the ledger `0600`, and `-wal`/`-shm` are held to `0600` whenever they exist; those two exist only while a connection is open, so the modes are applied after the connection is up, on every open, which also heals an install a `0.2.0` release left world-readable. A data directory that already exists keeps the mode its owner gave it: the commands that create a ledger repair the ledger and the files beside it, not a directory the person chose. `traj schema init` states both modes in its output fields, because a help `note` is the release annotation only (ADR-0034).

## Considered options

Reading a project's `bunfig.toml` as configuration was never a feature, and no caller asked for one. Honouring a working directory's `.env` was rejected for the same reason it was reported: a cloned repository could point `TRAJ_HOME` at a path it controls. Keeping the create-on-open behaviour for writes only was rejected as two rules where one reads better, and because the empty ledger the QA found came from a read. Making `restore` require an `init` first was rejected: it adds a third step to the replacement ADR-0038 describes in two, and the restore is no more a side effect than the `init` beside it. Relying on the user's umask was rejected because the mode of the ledger is not the user's to remember. An environment flag to opt the autoload back in was rejected: it would be off by default anyway, and the property it turns off is a security one.

## Consequences

A fresh machine's first command is `traj init`; a script that reads before it initialises now exits 4 and must handle that. `traj doctor` reports a missing ledger instead of creating one (ADR-0038), and `traj data remove` followed by `traj restore` recreates the database from the backup the removal checked. The `-wal`/`-shm` modes are observable only while a connection is open, since SQLite deletes both on a clean close. The guarantee is the compiled binary's: the npm launcher is a Node script that reads neither file, while `bunx` starts under Bun itself and Bun reads the working directory's `bunfig.toml` before any `traj` code runs, which no package can prevent — the install script and `npx` channels do not have that limit.
